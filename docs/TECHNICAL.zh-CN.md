## 二、三个信念

每个信念先说结论，再给实测，最后说我们因此造了什么。

### 2.1 任何一个特定领域，都藏着一个相关性极高的隐形规律——找到它，几 MB 就能还原一大截能力

**结论。** 站在某一个领域看，量化带来的损伤不是均匀的噪声。同一个领域的文本反复走的只是一小撮方向，
沿这些方向的误差，几千个 token 就能学出来。修掉它，每字节换回的能力比给权重多加几位多得多。

**实测。**

- **五个领域，同一套做法。** 金融、编程、法律、医疗、科研各用同一个解算器解出一份侧车。在各自的留出文本上，
  top-1 一致率 **+2.8 到 +3.7 个点**，平均 KL 降 **16–28%**（表格见 5.1）。
- **不伤通用。** 在英文维基上，五个侧车挂哪一个，top-1 一致率都从 78.5% 升到 **80.7–82.8%**，
  Σmin 从 0.769 升到 **0.787–0.801**。
- **杠杆。** 按实测的位宽曲线，+3 个点大约相当于每个权重多 0.15 bit，也就是专家多占约 11 GB。
  而做到这件事的侧车只有约 **40 MB**。

**因此我们造了：** 一个从不看领域数据的通用基座，加一个每个领域一份的小侧车（见 4.2）。

### 2.2 相信缩放定律；模型里知识的分布就是哈希随机的

**结论。** 能力跟着留下来的字节走。想靠"某些专家、某些层、某些矩阵更重要"去绕开缩放定律是行不通的——
权重里根本没有这种结构，路由的行为就像对 token 做哈希。硬件同理，边际效用递减：再买一台机器，
换回的能力远不到成本的比例。

**实测。**

- **权重没有"偏心"。** 在真实权重上量：同一层 384 个专家的相对量化误差一致到 **1.9%** 以内；专家能量
  最大最小只差 **1.25 倍**；层与层的 Σw² 只差 **3%**；一个专家的三个矩阵各占 **33.5 / 33.3 / 33.2**。
  把一个 bit 从 B 挪给 A，只有 A 的重要性至少是 B 的 **1.189 倍**才划算——因为每 8 个权重多 1 bit，
  误差乘 1/1.189（实测 11 / 12 / 13 bit 时相对误差 0.201 / 0.171 / 0.143）。没有任何一个粒度跨过这条线，
  所以"动态分配"的最优解就是均匀分配；按层、按专家动态分配的实现实测没有收益。
- **路由就是哈希。** 量化之后，中深层"6 个专家和原模型完全选中同一组"的 token 只剩 1.6–28%，而按专家
  统计的系统性偏差只能解释其中 3–22% 的翻转，剩下的全是逐 token 随机的。相邻 token 几乎不共用专家：
  连续 1、2、3、4、5 个 token 碰到的不同专家数是 6、10.0、13.3、17.4、21.7。
- **剪专家本质上是在偷偷选领域。** 唯一有 20–80 倍跨度的信号，是"在某份语料上"各专家被选中的频率——
  换份语料，频率就变。要靠剪枝塞进 100 GB，每层 384 个专家只能留 130 个。
- **加位宽，边际递减**（只量化专家，英文维基尺）：每权重 1.0 / 1.5 / 2.0 / 2.5 / 3.0 bit →
  Σmin 0.445 / 0.746 / 0.848 / 0.900 / 0.927。最后半个 bit 只换来 +0.027。
- **加机器，边际递减。** 解码速度由每个 token 要读多少字节决定。按层切到两台机器上，每个 token 都要多走
  一跳网络（上游 ds4 在两台 Mac 上实测 −19%）；张量并行能把字节对半分，但我们的双机实测只有 1.25 倍，
  一半收益被 all-reduce 吃掉。作为参照：社区用两台 Spark、FP8、TP=2 加投机解码跑体积更小的 V4 Flash
  （284B），约 41 token/s；这里一台 Spark 跑 V4.1 是 42–46。

**因此我们造了：** 一台机器；每个字节均匀地花；剩下的能力靠侧车和后训练补，不靠堆拓扑。

### 2.3 真实场景下开源模型不够用——不只要量化，还要后训练，而且数据必须留在本机

**结论。** 真实业务——一个真实的代码仓库、一张真实的交易台——开源模型开箱即用是不够的，而且量化保真度
解决不了这个问题：把原模型复制得再像，也会把原模型的错误一起复制过来。模型必须从自己的部署里学习，
而这些数据（持仓、复盘、源代码）不应该离开这台机器。

**实测。** 试验场是一条由 ds4 提供服务的交易 Agent 流水线（大盘研判、新闻归并、选股、CFO 决策报告，
提示长度 9k–132k token）。模型定的目标价 **12 个全部高于次日实际最高价**。一条大盘研判请求上，模型的
结论是"大盘上涨"，当天实际 1,891 家上涨、3,563 家下跌。

**因此我们造了：** 第三个文件——在本机上用一份普通的问答文件训出来，叠在最上面，不碰 ① 也不碰 ②（见 4.3）。

## 三、架构：通用基座 + 专业侧车 + 后训练文件

```
                  是什么                             多久变一次
 ① 基座 GGUF      113.6 GB，通用，零语料             从官方权重量化一次，之后不再动
 ② 侧车           每个领域约 40 MB  (--zchain)       每个领域解一次，然后冻结
 ③ 后训练         约 100 MB         (--posttrain)    用你自己的数据训；删掉它就是回滚
 ──────────────────────────────────────────────────────────────────────────
 每个路由专家的每一行权重:   g_实际 = g_基座 × s_侧车
 每层的路由器:               选择分 += Δb_侧车
 每层 MoE 的输出:            y += x · B · A      (③，每层秩 64)
```

- **① 单独就是一个完整模型。** ② 只给已有的权重行乘一个缩放、给路由器加一点偏置；③ 给每层 MoE 的输出
  加一个小的低秩项。都不加层，挂不挂它们跑的都是同一套核。
- **运行时几乎零成本。** ② 每解码一个 token 多读约 0.6 MB，是基座读量的 0.01% 左右；③ 每层只多两个小矩阵乘。
- **配对有指纹。** ③ 里存着它训练时所依据的那份 ② 的哈希（`base.fnv`），对不上引擎直接拒绝加载。
  不做这道检查的话，过期的 ③ 照样能跑，只会悄悄给出错的结果。

```sh
./bin/ds4-server --cuda -m base.gguf --zchain 侧车目录/ [--posttrain 后训练目录/] --mem-budget-mb 110000
```

## 四、算法

### 4.1 基座：8 维向量量化 + 每层共享码本

**一句话。** 路由专家每一行里，每连续 8 个权重换成码本里的一个 12 bit（或 13 bit）编号，再乘上这一行的
一个增益。

**直觉。** 官方专家本来就是 FP4，每 32 个权重带一个缩放（合 4.25 bit/权重）。想用标量格式压得比这更低，
光是养这些缩放就要 0.25 bit/权重。向量量化（VQ）把 8 个权重一起编码，同样的位数下能突破标量的率失真界，
而且每行只要一个增益就够——前提是一行内部的动态范围不大。实测（第 0、20、39 层）行内官方缩放平均只差
2 倍、最坏 4 倍，一个行增益完全罩得住。

**格式。**

```
w[r, 8j : 8j+8]  ≈  g_r · C[ idx[r, j] ]        C = 4096 × 8（12 bit）或 8192 × 8（13 bit）
每权重位数       =  12/8 = 1.5  或  13/8 = 1.625，另加每行一个 f16 增益（约 0.003）
```

**码本怎么训。**

1. 每一行先除以它自己的 RMS，得到 `g_r`。
2. 在 GPU 上跑 Lloyd 迭代。指派这一步是融合的：码本按 512 条一块流过 shared memory，每个线程在寄存器里
   维护自己的 argmin，距离矩阵从不落地（直接用 cuBLAS 算 `G = V·Cᵀ` 的朴素版本，每个专家要搬 144 GB）。
   向量维度写成模板参数，8 个值才能留在寄存器里——比运行期维度快 3 倍。
3. 构造上就是确定的：初值等距采样（没有随机源）、固定轮数、更新步用双精度原子加。同样的输入，同样的字节。
4. 最后一次指派用的是已经舍入到落盘精度的码本和增益，所以量化器报出来的误差，就是引擎实际会看到的误差。

**每层一本码本，384 个专家、三个矩阵共用。** 因为专家们在统计上是同一个形状（相对误差一致到 1.9%），
用每个码字至少 1,000 个训练向量的池子训一本层码本，几乎没有代价：第 20 层误差 0.17062，每专家一本是
0.17072（反而略好）；第 39 层亏 0.33%；平均亏 0.15%。换来的是省掉 15,744 本码本，**3.09 GB**。
池子厚度很关键：薄 4 倍的池子，13 bit 层上亏 0.96%。

**码字存成 FP8（E4M3）。** 误差只多 0.12%，查表字节减半。但解码必须走硬件转换指令
（`cvt.rn.f16x2.e4m3x2`，sm_89 及以上）；标量转换函数数值逐位正确，但解码慢 26%、预填慢 20%。

**省下的 3.09 GB 花在哪：最浅的 14 层从 12 bit 升到 13 bit**（误差 −16.1%）。误差曲线是凸的（降 1 bit 亏
5.3 个点，升 1 bit 只赚 2.6–3.7 个点），多出来的字节要摊薄、不能堆：14 层升 13 bit 比 7 层升 14 bit
消掉的总误差更多；而且实测浅层每 GB 的价值是深层的 1.2–1.4 倍。

**"12 + 1" 位平面布局。** 直接按 13 bit 排，一块 256 个编号是 104 个字 = 3.25 条缓存线，每次 128 字节的读
都会跨两条线。在 GB10 上，读不满整条 128 字节线的访存会从约 219 GB/s 掉到约 142 GB/s（我们用
`mem_ceiling` 探针量死的）。所以 13 bit 层保留一条与 12 bit 层几何完全相同的 12 bit 主流（一块正好
3 条整线），第 13 位单独放一个位平面：每块多一条 32 位读、每轮多一次 warp shuffle。

**出错要出得响。** 第三版载荷换了新魔数（`DQV3`），加载器按格式版本白名单放行。不认识这个格式的引擎在
加载时直接拒绝；比白名单还老的引擎会从第一句话起输出全零的专家。两种情况都不可能算出一堆看着像样的假数。

**零语料。** 基座只从权重量化，不看任何语料。金融语料加权校准的结果是金融尺持平、通用尺退 2.4 个点：
领域知识该放进 ②，不该放进 ①。

**113.56 GB 由什么组成。**

| 部件 | 格式 | GB |
|---|---|---:|
| 路由专家编号 | VQ-8，26 层 × 12 bit + 14 层 × 13 bit | 104.90 |
| 行增益 | f16 | 0.30 |
| 码本 | 40 本 × E4M3 | 0.003 |
| 注意力、共享专家、输出头 | q4_K | 4.96 |
| 投机解码草稿塔 | VQ-8，12 bit | 2.56 |
| 其余 | 原样 | 0.85 |

**证据。** 与同体积的对照基座（每专家一本码本、全部 12 bit）比：top-1 一致率 金融 **+1.9**、英文
**+2.5** 个点；最差的 5% 位置涨得最多（Σmin p5 +22% / +83%）。在英文上，本基座什么都不挂就超过对照基座
挂上侧车的成绩。

### 4.2 专业场景侧车（反修）

我们把求解这件事叫**反修**，它的产物叫**放大器**；侧车就是一个装着放大器文件的目录。

**一句话。** 给每个专家的 down 投影的每个输出通道重新解一个乘性增益，再给每个专家解一个路由偏置，
让每个量化后的 MoE 块在领域文本上重现原模型这一块的输出。

**为什么是增益，不是加性修正。** 只要修正是块输入 x 的线性函数（例如低秩的 `y += B·A·x`），它在模型
出口上的一阶效应就约等于 0：层内留出集误差消掉 9%，端到端指标照样变差（步长扫描确认）。逐专家增益注入的
修正 `Δ = Σ_e rw_e · (s_e − 1) ⊙ y_e` 取决于路由选中了哪几个专家、以及每个专家自己的隐状态，**不是** x 的
线性函数，所以能真正推动出口。

**目标函数（逐层）。**

```
y_i   = Σ_k rw_ik · ( s_{e_ik} ⊙ ye_ik ) + ysh_i          # 就是引擎自己的 MoE 求和
        ye = 专家 down 投影输出（乘路由权重之前），ysh = 共享专家输出

min_s   Σ_i ‖ y_i − y_i^原 ‖²   +   λ · Σ_d  d̄_d · Σ_e ( s_e[d] − 1 )²
```

- `y^原` 是原模型在同一位置、同一块的输出，来自教师夹具：DeepSeek 官方代码、全精度、40 层 × 全部拟合
  token，每份拟合语料只落一次（8,192 token 是 14 GB）。
- 增益是对角的，所以 5,120 个输出通道彼此独立，每个通道就是一个 384 个未知数的最小二乘。
- 解法是**逐专家 Gauss–Seidel**（3 轮）：每个专家只碰路由到它的那约 128 行，解完立刻更新残差——
  从来不组 384 × 384 的方程。
- 岭的尺度 `d̄_d` 取**这个通道上所有专家的平均能量**。若用每个专家自己的能量，被选中次数少的专家会被
  少数几行推到极端：第 0 层拟合 +32.7%、留出集 −2685%；用共享尺度，同一层留出集 +27.0%。

**在部署同路上拟合，一层接一层。**

- `ye` 和 `ysh` 直接从引擎自己的预填核里的钩子取，不另写一份实现重算。每层都要过一道硬检查：
  `round_bf16(Σ rw·ye + ysh)` 与引擎的块输出在 99.996% 的数值上逐位相同，否则停车。
- 40 层按 0 → 39 一遍走完。解第 k 层时，前 k 层的解已经挂上，所以它看到的上游就是部署时真实的上游。
- 每一层：先解路由偏置 Δb → 挂上 → 重新取料 → 再解增益。
- `λ ∈ {0.01, 0.1, 1, 10, 100, 1000}`，只看留出集选。留出集按来源窗口分层切（每 4 个 128 token 窗口取
  1 个，即四分之一的 token），保证每个子来源两边都有。
- **留出集收益超过 0.5% 的层才挂。** 这是显著性闸，不是为了省体积：6 个 λ 里挑最好的，纯噪声也能挑出
  一个略大于 0 的数；而在序贯链上，一个噪声层会污染它后面的每一层。端到端尺上，"大于 0 就挂"四项指标
  全部变差。

**FP4 格点直解。** 增益用 FP4 存（E2M1，每 32 个一个缩放）。先按浮点解完再舍入，会白扔 11% 的修正量——
E2M1 只有 8 个幅值格点。所以把 Gauss–Seidel 的每一步拆成三步：解一个专家 → 把 `s − 1` 投影到 FP4 格点、
直接产出 17 字节的块 → 用**格点值**更新残差。专家 e 的舍入误差由排在它后面的专家当场吸收——与 GPTQ 的
误差补偿同构，只是未知数换成了一维增益。第 0 层只丢 0.27 个点而不是 11%；侧车从 **291 MB 缩到
38.6 MB**，五项指标一项没退。落盘写的就是格点码字本身，保存前用引擎自己的解码器回读逐位自证。

**路由偏置 Δb。** 逐层逐专家，累计原模型选中集合与我们选中集合之间的选择分缺口：原模型选了 e、我们没选，
加 `thr − v_e`；我们选了 e、原模型没选，减 `v_e − thr`（`thr` = 我们第 K 名的选择分）。取平均，事件数
≥ 8 的专家才武装，再乘 `α ∈ {0.5, 1, 1.5, 2.5}`（按留出集"与原模型同集率"挑），留出集严格变好的层才落盘。
Δb 只加进选择分，混合权重不动。原模型的路由用夹具里的全精度输入、模型自己的 bf16 路由器重算；
重算结果与引擎的选择至少 99% 一致，否则后面全是假账。

**代价。** 同一个解算器、同一套闸，每个领域在 Spark 上跑一趟：

| 侧车 | 拟合语料 | 增益 / 路由偏置 | 体积 | 教师夹具 + 40 层解算 |
|---|---|---|---:|---|
| 金融 | 8,192 token，五个中文金融来源 | 39 / 27 层 | 40.8 MB | 27 + 73 分钟 |
| 编程 | 15,360 token，30 种编程语言 × 512 | 39 / 29 层 | 40.8 MB | 31 + 124 分钟 |
| 法律 | 15,360 token，6 个来源 × 2,560（3 中 3 英） | 40 / 24 层 | 41.8 MB | 31 + 104 分钟 |
| 医疗 | 15,360 token，6 个来源 × 2,560（3 中 3 英） | 40 / 29 层 | 41.8 MB | 32 + 115 分钟 |
| 科研 | 15,360 token，6 个来源 × 2,560（3 中 3 英） | 40 / 29 层 | 41.8 MB | 32 + 104 分钟 |

**证据**（top-1 一致率，成对跑；完整表格见 5.1）。金融：增益 71.7 → 73.9%；增益固定、再加路由偏置
+0.24 个点、KL −2.5%（英文 +0.78 个点、KL −3.8%）。挂本域侧车：编程 78.6 → 82.3%、法律 72.9 → 76.4%、
医疗 69.1 → 72.8%、科研 71.7 → 74.9%。

### 4.3 后训练文件

**一句话。** 给每层 MoE 加一个秩 64 的低秩项（`y += x·B·A`），穿过引擎自己的 GPU 前向做反向传播来训，
数据只是一份问答 jsonl。

**数据。** 一行一条，两种写法，就是 Unsloth 训练器收的那两种（对话 `messages`，或续训用的原文 `text`）：

```json
{"messages":[{"role":"user","content":"…"},{"role":"assistant","content":"…"}],"context":"可选的原文材料"}
{"text":"一段原文，不套聊天模板"}
```

**三种目标，按行自动选。**

- **`text`**（续训）。序列 = BOS + 原文 + EOS，每个 token 都是目标（交叉熵）。超过 `maxlen` 的行按 token 切成连续
  几段各自成样本，不丢尾。先把文档出成问答再训（`gen`）是可选的数据工具，不是训练的一环。

- **带 `context`**（上下文蒸馏）。老师 = 部署态模型（① + ②）把材料放进提示里答题；学生 = 同一个模型加 ③、
  不看材料答同一题。损失是答案位置上老师下一 token 分布到学生分布的 KL。说白了就是让模型学会"像刚读过这份材料
  那样回答"，所以文件里没问过的问题也能用上。
- **不带 `context`**（普通 SFT）。目标就是答案本身（答案 token 的交叉熵）。

**守住通用能力。** 每次训练都自动混入一份固定的保持料（`gguf-tools/data/posttrain/hold.jsonl`，63 道通用题，
答案是部署态自己答的），老师就是部署态自己。它把 ③ 在训练文件管不到的地方钉住。

**选哪一轮。** 每五题按题面哈希留出一题。每轮结束量一次留出损失，再用 WikiText-2 查通用英文：Σmin 退不超过
0.5 个点、平均 KL 涨不超过 3% 才算过门。过门的轮里留出损失最低的那一轮就是 ③。老师的分布只算一次，缓存在数据
文件旁边，同一份数据再训就跳过这步。

**为什么用反向传播，不用闭式解。** 上一版把"这个位置该写 *a* 不该写 *b*"线性化到末层增益上，几秒就解完。
它能翻掉指定的 token（训练请求上 55% → 88%，其他位置 99.66% 不变），但换个交易日一点不迁移：翻一个 token 只改
一句话，改不动整条推理链；而且答案位的激活不像拟合行时就根本不点火。公开的"把文档写进权重"的方法（knowledge
modules、prompt distillation、cartridges、自蒸馏）全是梯度训练、以老师分布当目标——这一版就是这么做的。

**证据。** 一台 DGX Spark，一份真实数据：20 篇交易复盘出的 1,326 道题（另加 63 道保持料），3 轮，0–39 层，
学习率 2e-4，端到端 72 分钟：

| | 留出损失 | 保持料 KL | WikiText-2 Σmin | WikiText-2 平均 KL | WikiText-2 top-1 一致率 |
|---|---:|---:|---:|---:|---:|
| 训练前（① + ②） | 1.766 | 0.006 | 0.7887 | 0.6170 | 80.27% |
| 第 1 轮 | 0.865 | 0.093 | −0.24 个点 | −4.6% | |
| 第 2 轮 | 0.731 | 0.121 | −0.40 个点 | −8.5% | |
| **第 3 轮（选中）** | **0.646** | 0.116 | **+0.50 个点** | **−10.6%** | **82.81%** |

第 3 轮之后，对留出题贪心作答，问到的四个数字（入场价 30.39、目标价 25.57、止损 28.03、偏差 −4.89%）逐位答对；
通用题（地球公转、一句翻译）答得和训练前一样。

**安全。** ③ 是独立目录，带它训练时那份 ② 的指纹（`base.fnv`），配错引擎直接拒绝加载。删掉目录就是回滚。

### 4.4 引擎

**一句话。** 热路径上的每一个核都是为这个格式、在 GB10 上专门写的；每一次提速都必须保证温度 0 的输出
逐字节不变。

**墙在哪。** 解码是访存受限的：每个 token 要读约 6.3 GB。按 GB10 实测约 235 GB/s 算是 26.8 ms
（37 token/s）。我们现在是 32.5 ms——**贴到墙的 82%**。

| 每解码一个 token | 字节 | 核跑到的带宽 |
|---|---:|---:|
| 输出头（q4_K） | 372 MB | 约 249 GB/s |
| 注意力与共享专家投影（q4_K） | 约 3.6 GB | 193–210 GB/s |
| 路由专家（VQ，每层 384 选 6） | 1.64 GB | 约 155 GB/s |
| n-gram 记忆投影（FP8） | 314 MB | 约 226 GB/s |
| 路由器与小混合矩阵 | 314 MB | 132–136 GB/s |

**解码。**

- **VQ 专家核。** 常驻核。每层码本每个 SM 只搬进 shared memory 一次。编号流按 384 字节一块读
  （正好 3 条整 128 字节线），用 warp shuffle 分发码字；相邻行首尾相接流式读。加载时把每个专家载荷挪到
  编号流从 128 字节边界开始（只动设备副本，盘上文件不变）：每层 145–155 → 124–129 µs。
- **q4_K GEMV**（另外约 60% 的字节）。两种形态：*stage*（一个 CTA 先把整条线搬进 shared 再算）和
  *pipe*（常驻 + cp.async 双缓冲，给 4–12 KB 的组用）。每 token 22.9 → 18.8 ms。
- **整步 CUDA graph。** 每个位置桶捕获一次；token 位置放在设备槽里，重放不用重新捕获。暂存在捕获**之前**
  长够：捕获中途分配内存会让捕获作废，不走图每个 token 要 43.9 ms。
- **PDL（程序化依赖发射）。** 1,391 条核间边：每个核先预取自己的常量权重，再等上游。
- **侧流。** 注意力的 KV 支路和共享专家挂在侧流上，与主链并行。
- **长上下文。** 重写了稀疏注意力的选择核（1,024 线程的 top-k、读一批先发、一个 warp 推 4 组）：
  5.1 万上下文时每 token 的额外开销 4.6 → 2.8 ms。

**预填。** 专家走 bf16 张量核（`mma.m16n8k16`）。E4M3 码字转 bf16 是精确的，激活本来就在 bf16 格点上，
所以每个乘积都与标量路逐位相同。张量核内部长累加会丢低位（3.5% 的输出差 1 ulp），所以每个 k16 片单独从零
累加、再用一条 FADD 加回去（降到 0.5%）。提示按 2,048 token 一块处理：每一块都要把本层全部专家的位流解一遍
（每层 2.55 GB），块多大决定多少个 token 来摊这次解码。真实路由很偏（一块 2,048 token 只碰到 384 个专家里的
200–350 个，最热的一个吃掉 8–16% 的名额），所以一个工作项覆盖一个专家最多 128 个 token、16 个 warp 一起算，
12 位层的码本进 shared memory 时就转成 bf16。稀疏注意力是单遍 flash 核：查询的片段常驻寄存器，分数由
`mma.sync` 直算，在线 softmax 就地缩放输出累加器（`mma.m16n8k16` 的累加器布局是文档定死的，`wmma` 的不是），
每个键只 gather 一次。一块的 n-gram 记忆行由 I/O 线程在 GPU 算的同时读盘，只有最后一块的末位过出口头。
12.5k token 提示：**216.5 → 1,055 token/s**。质量在舍入噪声之内没变：金融判决切片 Σmin 0.7436 → 0.7441、
KL 0.5149 → 0.5131、top-1 一致率 74.56% → 74.77%；除注意力核外其余各处与标量路逐字节相同。

**投机解码。**

- 模型自带的三个草稿塔用同一套 VQ 量化（2.56 GB）。
- 验证批（1 + k 行）有专门的核：GEMV 走多行的 stage/pipe；专家走一个按"（去重后的专家 × 行）"派活的常驻核，
  同一个专家被多个 token 选中时位流只读一遍。
- **调度器。** 草稿头每个位置报一个置信 `c_j`。令存活率 `a_j = Π_{i≤j} σ(c_i)`，选

  ```
  k* = argmax_k  (1 + Σ_{j≤k} a_j) / (c_draft + c_v1 + c_tok · (1 + k))
  ```

  三个成本由引擎按请求自己量：走图纯解码一步、草稿一轮、验证 `1 + k` 行各自的墙钟（按已见过的行数做加权最小二乘，
  付懒分配的暖身轮不记）。头几轮先验最长的一块、再验一行，凑出拟合线要的两个点。没有编译期成本常量。存活率也在线校准：
  `ρ` = 本请求首位命中数 / Σσ(c_0)，乘到每个 `σ(c_i)` 上。墙钟只改 `k`，不改任何 token：任何 `k` 下投机输出都与
  纯解码逐字节相同，所以 `k` 随墙钟变是安全的。
- **保证**：温度 0 时投机的输出与纯贪心的输出逐字节相同，每次改动都验。贪心与采样请求都默认开。采样请求的草稿按草稿塔
  自己的分布抽（同一套温度与截断），验证是 GPU 上的拒绝采样（以 `min(1, p_目标/p_草稿)` 的概率接受草稿 token，否则从残差
  `max(0, p_目标 − p_草稿)` 里抽），所以 token 的分布与纯采样解码完全一样。"按分布抽"而不是"取塔的 argmax"是在固定文本上用
  解析尺定的（温 1.0 下首位期望接受率 0.69 → 0.74、0.63 → 0.76），不是靠测速——采样每趟都是另一篇文本。调度器的接受率
  校准按请求在线学，没有常量。采样本身也在解码图里的 GPU 核上做
  （Gumbel-max，`top_k`/`top_p`/`min_p` 截断用基数选择精确算；主机每行只读回 16 字节），有分布门守着
  （`make cuda-regression`）。
- **为什么没更快**：每多验一个 token 就多碰约 3.9 个新专家（哈希式路由，见 2.2），验 k + 1 个 token 远比验
  1 个贵。验证批现在只跑到它自己字节墙的 57%，这是下一根杠杆。

**内存。** 权重是 mmap 映射的。每条请求的状态按它真正用到的位置增长：1M 的 KV 本身 0.89 GB；每步的暂存
按需翻倍增长，不按 1M 一次开满（2.5 GB → 一条 4 万 token 的请求只用 160 MB）。logits 与出口头的暂存不再随
预填块长（一条生成请求只留 10 行 logits，不是 2,048 行）；一条 106.7k token 的请求走服务端，121 GB 的机器上
还剩 6.7 GB。没有上下文旋钮——边界来自 GGUF 元数据，传 `--ctx` 直接报错。

### 4.5 怎么量

**一句话。** 唯一的裁判是原模型——用 DeepSeek 官方代码、全精度跑；我们的引擎在它提供服务的同一条路径上打分。

- **教师**：DeepSeek 官方 PyTorch 推理代码，原始 FP4/FP8 权重按层从 SSD 流式加载（510 GB 放不进内存）。
  教师 logits 按（文本, 长度）缓存。
- **学生**：引擎的打分路（`--score-ids`），同一种文件格式，全部用同一个比较器（`anchor_metrics`）。
- **五个数**：top-1 一致率；Σmin（均值、中位、p5）；平均 KL(原模型 ‖ 我们)；PPL 比值。主判 Σmin 和 KL。
  只看 top-1 一致率太宽松——简单文本会把损伤藏起来（同一份文件在简单代码上能读 0.90，在硬文本上只有 0.52）。
- **互不重叠的切片**：每个领域的文本切成拟合份和判决份，永不混用；同一个来源（一篇文档、一个代码仓库）
  只进其中一份。

  | 尺 | 判决切片 | 原模型 PPL |
  |---|---|---:|
  | 金融 | 8,192 token，五个中文金融来源 | 6.978 |
  | 编程 | 15,360 token：30 种语言 × 512，取自 GitHub（`codeparrot/github-code-clean`），剥掉许可证头 | 4.766 |
  | 法律 | 15,360 token，6 × 2,560：中国法律法规、刑事案件公诉事实（CAIL2018）、司法考试真题（JEC-QA）；美国最高法院判决、欧盟法规、合同条款（LexGLUE） | 4.865 |
  | 医疗 | 15,360 token，6 × 2,560：医学百科问答、寻医问药真实医生回答（cMedQA2）、执业医师考试题与解析（CMExam）；PubMed 摘要、PMC 病例报告、USMLE 考题（MedQA） | 8.625 |

  | 英文 | WikiText-2，512 token | 1.657 |

- **成对、一次只动一个变量**：对比一律同一个二进制、同一趟跑。
- **五个数之外的门。**
  - 温度 0 逐字节一致：直发 == CUDA graph == 重放，投机 == 纯解码。
  - 换量化格式，还要过解码路的检查。五个数都在预填路上算，看不见解码核的错：13 bit 核用块号而不是组号
    推进位平面指针时，五个数全绿，解码路 PPL 却是 8.19 而不是 5.80。
  - 判断"停不停得下来"不设输出上限；带上限的一趟只能说明"到上限还没停"。

## 六、没走通的路

失败的结论和成功的一样撑着这个设计。每一行都是实测，不是推理。

| 想法 | 实测 | 结论 |
|---|---|---|
| 按层 / 专家 / 矩阵动态分配位宽 | 重要性跨度 3% / 1.25 倍 / 33:33:33；挪一个 bit 要 ≥ 1.189 倍 | 均匀就是最优 |
| 按行动态分配位宽 | 能量有 2.5 倍跨度，被码本代价和整数位宽吃光：净亏 1.6%–5.9% | 否决 |
| 剪专家塞进 100 GB | 每层 384 个只能留 130 个 | 否决：本质是偷偷选领域 |
| 低秩加性修正 `y += B·A·x` | 层内留出集 +9%，端到端为负；出口一阶效应约为 0 | 整族出局 |
| 均值 / 偏置校正量化误差 | 层内 +4 个点，出口 −0.33（3 层）；40 层 70.52 → 63.89% | 否决 |
| 用领域数据重解码本 | 65.43% 对 65.59% | 零收益 |
| VQ 编号熵编码 | 12 bit 的经验熵 11.927：只省 0.6% | 不值 |
| 熵约束 VQ + 变长流 | 扣掉流开销净剩约 0.1 bit | 不值 |
| 金融语料校准基座 | 金融持平，通用退 2.4 个点 | 基座坚持零语料 |
| 草稿词表裁成金融术语 | 在没见过的请求上 +0.2% 到 −54% | 否决 |
| 验证批多 token 分组专家核 | 码本查表省一半，时间一毫秒没省 | 否决 |
| 第二台机器分担解码 | 按层切 −19%（上游实测）；张量并行 1.25 倍 | 一台机器 |

## 七、手动安装与运行细节

一键安装和它的选项在 [README](../README.zh-CN.md#使用方式) 里。这一节是安装脚本做的事（想手动来可以照着做），
以及服务和页面的细节。

**[Hugging Face 仓库](https://huggingface.co/wenzhouwu/YoungAi-DeepSeek-V4.1-Flash)里有什么。**

| `DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative-grrb-code_fit_n15360-engine/` | ② 编程侧车，结构相同：增益 39 层，路由偏置 29 层 |

**第一步：下载并拼回基座。** 手动拼接时需要 227 GB 空闲空间（一键脚本只多占一份的空间，因为它每追加一份就删一份）。

```sh
hf download wenzhouwu/YoungAi-DeepSeek-V4.1-Flash --local-dir ds4-v41
cd ds4-v41
sha256sum -c --ignore-missing SHA256SUMS            # 每一份都必须显示 OK
cat DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative.gguf.part{01..40}-of-40 > DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative.gguf
sha256sum -c --ignore-missing SHA256SUMS            # 这次拼好的 .gguf 也要显示 OK
rm DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative.gguf.part*-of-40
chmod +x bin/ds4 bin/ds4-server                      # 下载不保留可执行权限
```

**第二步：n-gram 记忆表。** 它不在 Hugging Face 仓库里：引擎直接从官方权重的两个分片里原样读取（每个约 101.5 GB）。

```sh
hf download deepseek-ai/DeepSeek-V4.1-Flash \
    model-00047-of-00048.safetensors model-00048-of-00048.safetensors --local-dir /data/DeepSeek-V4.1-Flash
```

放哪个目录都行，下一步用 `--engram-dir` 告诉引擎。GGUF 里只记着这两个分片在“构建它的那台机器”上的路径，
你的机器上没有这个路径——不传 `--engram-dir`，引擎加载时会报警告，第一个请求就停在 `ds4: engram 表打不开 …`。

**第三步：起服务。**

```sh
cd ds4-v41
SIDECAR=DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative-grrb-vqfin41_vqhalf_a_n8192-engine    # 金融
# SIDECAR=DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative-grrb-code_fit_n15360-engine         # 编程
# SIDECAR=DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative-grrb-law_fit_n15360-engine          # 法律
# SIDECAR=DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative-grrb-med_fit_n15360-engine          # 医疗
# SIDECAR=DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative-grrb-sci_fit_n15360-engine          # 科研
./bin/ds4-server --cuda -m DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative.gguf --zchain $SIDECAR \
    --engram-dir /data/DeepSeek-V4.1-Flash --mem-budget-mb 110000 --host 0.0.0.0 --port 8000
```

加载大约两分钟。接口：`/v1/chat/completions`、`/v1/completions`、`/v1/responses`（OpenAI 风格）和
`/v1/messages`（Anthropic 风格）。请求里没带的采样参数按模型卡的推荐配方：`temperature` 1.0、`top_p` 1.0、
不设 `min_p`，在 GPU 上采样，投机解码照开（真实 14k token Agent 请求几趟 34–37 token/s，贪心 45.5）。要输出逐字节
可复现就显式传 `"temperature": 0`。
请求默认**不思考**。要思考按请求显式打开：`"reasoning_effort": "high"`（或 `"max"`）、`"thinking": {"type": "enabled"}`、
`"think": true`，或 `"model": "deepseek-reasoner"`。量化后的权重对"停"类决策（`</think>`、EOS）给的概率比 FP 模型低，
长思考段可能收不了口；在权重侧修好之前，不思考是安全的默认。
别把贪心当聊天默认：在"合格答案很少"的题上，贪心会在思考段逐字打转停不下来（例：让它写 5 个以"五"字结尾的成语）。

**监控页。** `http://主机:8000/monitor` 是引擎自己提供的浏览器页面（零依赖，与 API 同源）：模型状态（读提示 / 生成进度条）、
解码与预填的 token/s 及一分钟火花线、GPU 负载 / 显存 / 温度 / 功耗 / PCIe、CPU、内存、磁盘读、上下文占用、最近请求
（提示 / 复用 / 输出 token、t/s、草稿接受、首 token 延迟、用时）和开服以来的累计。数据来自 `GET /metrics`：默认 JSON
（`?requests=all` 给全部保留的请求）；用 `Accept: text/plain` 或 `?format=prometheus` 请求就给 Prometheus 文本，
指标名用 vLLM 的，给 vLLM 写的 Grafana 看板不改一行就能读这台服务。平台读不到的量（macOS 的 GPU 温度）给 `null`，不编数。
统一内存机器（GB10）上"显存"卡显示的是物理内存（128 GB，取自内核的在线内存块），副标题带上内核自己能分配的量
（121.7 GB，`MemTotal`）。页面中英双语（跟浏览器语言，可切换，`?lang=en`）。板块与指标键照 Strata 的 Monitor 页
（github.com/Niko1221/Strata）对齐，两边可以并排对照。

这个页面和 `/` 上的工作台都是从"服务启动目录下的 `web/`"读的。在源码目录里启动就有；`install.sh` 装出来的目录
没有 `web/`，页面会返回 404，API 照常可用。

**命令行。**

```sh
./bin/ds4 --cuda -m DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative.gguf --zchain $SIDECAR \
    --engram-dir /data/DeepSeek-V4.1-Flash -p "解释一下什么是市盈率。"
# 默认按模型卡配方采样（纯解码）；加 --temp 0 走贪心 + 投机，再加 --no-dspark 是纯贪心（测速度基线时用）；
# 去掉 --zchain 就是裸基座
```

**发布的那份后训练文件是旧实验。** `posttrain-experimental-20260924/` 是上一版闭式解（见 4.3）在一条大盘研判
请求上解出的末层增益，只用来展示格式和加载方式；你自己训出来的 ③ 用同样的方式加载。`base.fnv` 是金融侧车的
指纹，所以这一份只能叠在金融侧车上，配别的侧车引擎直接拒绝加载：

```sh
./bin/ds4-server … --zchain DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative-grrb-vqfin41_vqhalf_a_n8192-engine \
    --posttrain posttrain-experimental-20260924
```

### 在 Mac 上编译和运行

V4.1 用到的每一个 GPU 操作都有 Metal 实现，逐核照 CUDA 版转写：前向、VQ 专家解码（12 bit 和 13 bit
位平面）、侧车增益与路由偏置、GPU 采样与投机验证，以及后训练要用的反向传播。`./ds4_test --metal-v41` 在真
Apple GPU 上用合成数据对 CPU 参考核了 126 项（不需要模型）：VQ 专家解码逐位相同；其余矩阵乘误差约 1e-4，在模型舍到
bf16 的地方逐元素相同；注意力差在一个 bf16 舍入格以内；每个反向核都过了有限差分检查。

**还没做的**：在 Mac 上跑真模型。基座要整个常驻内存（113.6 GB），而我们手上的 Mac 只有 16 GB，所以还没有任何 Mac 上的
速度和质量数字，128 GB 的 Mac 实际够不够也没验过。眼下它也跑不满硬件：Metal 没有流捕获，每个 token 只能一个核一个核
地发，不能像 CUDA 那样整步录成一张图重放；预填用的是 f32 瓦片，没用上 GPU 的矩阵单元；注意力只有标量版的核。

想在内存够大的 Mac 上试：`install.sh` 只支持 Linux，第一、二步手动做（`sha256sum -c` 换成 `shasum -a 256 -c`；`chmod`
那步跳过——下载来的 `bin/` 是 Linux 的），然后用自己编的二进制在源码目录里起服务：

```sh
./ds4-server --metal -m /path/to/DeepSeek-V4.1-Flash-vq8sh14-q4k-mtpnative.gguf --zchain /path/to/$SIDECAR \
    --engram-dir /path/to/DeepSeek-V4.1-Flash --mem-budget-mb 110000 --port 8000
```

必须在源码目录里启动（或传 `--chdir <源码目录>`）：Metal shader 是启动时按相对路径从 `metal/*.metal` 现编的，
把二进制拷到别处就找不到它们。

## 八、诚实的现状与局限

- **后训练（③）目前只用留出损失和 WikiText-2 门判**，真实数据只跑过一份（见 4.3），还没按端到端的业务结果评过。
  工作台上的训练眼下调用的是给我们这台 Spark 写的脚本（`gguf-tools/scripts/`，仓库在 `~/ds4-main`，模型在
  `gguf/v41/` 下）。
- **五个领域。** 金融、编程、法律、医疗、科研（指标见 5.1），五个侧车都在 Hugging Face 仓库里。所有侧车都只在留出文本上做过 teacher-forced 判决，还没在端到端任务上评过（Agent 式编程、
  法律或临床问答）。
- **只在一种机器上端到端验过。** 本页所有数字都来自 DGX Spark。Metal 后端过了逐核测试，但还没跑过真模型
  （见第七节"在 Mac 上编译和运行"）。
- **张量核预填不是逐位相同**：专家核对老的融合路径、单遍 flash 注意力对两遍扫键的旧核，差距都在舍入噪声量级（见 4.4）。

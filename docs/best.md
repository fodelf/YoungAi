先把三个词说白: **基座** = 量化文件本身(GGUF, 一个字节不动); **反修** = 在基座旁边解一个小侧车文件, 引擎加载时挂上去修量化误差,

### 1.3 增益反修现役形态(要改的就是它)

- 靶 = FP 出厂权重在**学生自己的输入与路由**上算的整块输出 y_fp(x_q, r_q)(FP 自洽口径, 08-20 铁律; 链态靶 y_fp(x_fp) 会自我拆台), 未知数 = 每专家每输出通道的缩放 s_e[d](锚 1), 每个通道独立的一维带岭最小二乘, Gauss-Seidel 逐专家 3 轮, **每解一个专家立刻投影到 fp4 格点并按格点值更新残差**(格点直解, 落盘零转换损失);
  岭尺度 = 本通道全体专家能量均值(冷门专家被拉回 1); λ 网格 {0.01, 0.1, 1, 10, 100, 1000} 只认 held-out val; 层 val ≤ 0.5% 不挂。
- shared 专家输出 ysh 在残差里是**固定项**: resid = y_fp − ysh − Σ_k s·rw·ye。**它自己的量化误差(q4_K, cos 0.9974 ≈ 7% 相对误差)现在被摊给了路由专家的增益去补**——这是错位归因, 下一节修。
- 引擎: `ds4_gpu_v41_set_gr_override(层, [E][D])`, 三条核路(解码融合核 / 预填融合核 / NVFP4 存档路)在算完 down 一行的点积后乘 `g_r × 覆盖表`(cuda_vq_prefill_fused.inc.cu `v41_vq_row_dotN` 末尾 `m.gov`), 解码字节零增量。
  预填融合路把 gate 输出 g32 与 SwiGLU 出口 h32 都**物化在设备缓冲里**(`g_vqpf.g32 / h32`, 按 (token,pick) 排序行), 取 h 与今天取 ye 是同一种拷贝。

## 2 路由反修: 怎么加进链里, 估计量怎么改进

### 2.1 机理(把"随机翻转"说清楚)

第 L 层路由: z = Wg·x(Wg bf16, 与 FP 同一份字节), p = sqrt(softplus(z)), 选择分 s = p + b(b = exp_probs_b), 取 s 最大的 6 个, 权重 = p/Σp × 1.5。
学生与 FP 的唯一差别是输入: x_q(量化链走到这一层的隐态) vs x_fp。logits 之差 Δz = Wg·(x_q − x_fp) = Wg·δ。
把 δ 拆成三份: ①常数份(与 token 无关的平均偏移) ②线性份(能由 x_q 线性预测的部分) ③剩下的逐 token 噪声。
现役 Δb 只修①的一个粗估计; 09-20 的账说①很小(3~22%); ②从没量过; ③任何静态参数都修不了——只有让上游更保真(那是增益反修的活)。
所以改进估计量的目标就是把①估准、把②量出来; 两列份额诊断(§2.3)随链一起报, 不当门。

### 2.2 夹具与链里的位置(现有设计, 一字不改)

- **夹具** = FP 教师在拟合份 a 8192 上自然跑一趟, 落每层 MoE 入口的 x_fp 与出口 y_fp(`v41_teacher.py --ids vqhalf_a.ids --ntok 8192 --dump-moe <目录>`, 40 层 × 168 MB × 2 = 14 GB, 先例 1594 s; 09-20 已验评估器在 x_fp 上重算的 y 与 dump 的 y 相对差 < 1e-3)。
  只落一次, 落完就是普通文件; 换拟合份才要重落。09-20 清理时删了, 本轮随链重落。
- **靶** = 工具拿 x_fp 重算 FP 路由(`v41_route_recompute_gpu`, 与引擎 `v41_router_kernel` 逐式同: bf16 gate f32 累加 → sqrt(softplus) → +bias → top-6 同分取小号, 09-20 自检与钩子 sel 同集 100%), 得 FP 集合 A_i; 学生集合 B_i 与 384 个选择分 s_q 由同一钩子在部署态重算。
  为什么靶必须是链态 x_fp 而不是 FP 自洽口径: 路由的 FP 自洽靶(FP 在 x_q 上选谁)与学生逐位同(gate 同一份字节), 没有信息; 路由反修修的就是"学生在漂移后的 x_q 上还该选 FP 在 x_fp 上选的那些", 只有链态给得出。
- **链里的位置**(09-20 合并序贯 grrb, 现役代码): 第 k 遍钩子同时收路由统计与增益取料 → 解本层 Δb → val 严格涨才落 rb_Lk.bin → 落了盘就挂上重取本层 → 解增益。引擎一个加载点 `ds4_gpu_v41_set_rb_override`(路由核的 bias = 盘上 bias + Δb, 权重分不动)。
- 出错会怎样: 夹具与 ids 错配 ⇒ 工具自检"重算路由与钩子同集 < 99%"硬停(RB_SEL_CHECK); 夹具缺文件 ⇒ 开钩子时硬停; 都不会出假数。

### 2.3 估计量(全部闭式, 全在反修工具里, 零 Python; 现役 E0 是底线, E1/E2 在 P3 与它 A/B)

数据(合并序贯第 k 遍的钩子里就有, 不加前向): 拟合行 i、专家 e 的 学生选择分 s_q[i][e](工具重算 384 个)、FP 选择分 s_fp[i][e](夹具 x_fp 重算)、FP 集合 A_i、学生集合 B_i。

| 估计量 | 未知数 | 解 | 引擎侧 | 修的是 |
|---|---|---|---|---|
| E0 现役 | Δb[E] | 错位事件 margin 缺口均值 × α | 有(rb 覆盖) | ①的粗估 |
| **E1 稠密常数** | Δb[E] | Δb_e = Σ_i (s_fp−s_q)[i][e] / (n + λ), 每专家 6144 个样本而不是 ≥8 个错位事件, λ 由 val 选 | 有(同 rb 文件格式, 引擎零改) | ①的正经估计 |
| **E2 逐专家仿射** | (a_e, c_e)[E] | z 空间一维回归 z_fp,e ≈ a_e·z_q,e + c_e(对付"量化把 x 的范数系统性缩了, 所有 logit 同比缩、与常数 b 的排位关系变了"这一类) | 路由核加 2E 个数(z ← a·z + c, 影响选择也影响权重; 按机制命名 ra_Lnn.bin) | ①+一点② |
| E3 线性 | ΔWg[E][D] 岭回归 x_q → z_fp, 或秩 ≤64 截断 | 5120² 正规方程, GPU 秒级; 本轮只报 val R²(② 的份额)不部署; R² ≥ 5% 再立项建引擎路 | 秩 64: 每层 0.7 MB + 两发小 GEMM | ② |

**择优尺换掉**: 同集率(6/6 全同)对近平局翻转过分敏感(第 6 名与第 7 名差 0.001 也算错), 出口不在乎这种翻转。改用**路由代价** R_i = Σ_{e∈A_i} s_fp[i][e] − Σ_{e∈B'_i} s_fp[i][e] ≥ 0
(学生修正后的集合 B' 在 FP 尺上比 FP 集合少拿的分; 近平局翻转 ≈ 0, 错得离谱才大), val 行上 mean R 降且平均交集数(0~6)不降才算涨; 层闸 = 严格涨才落盘(与现役同)。
**每层还多报两列诊断**: ①份额 = 常数估计量在 val 上解释的 Var(Δs) 比例, ②份额 = 线性估计量的 val R²——随 manifest 一起落, 只报不判。

### 2.4 为什么 wt2 会赔、怎么防

Δb 里的域先验(金融语料上 FP 更爱选哪些专家)在英文通用尺上是纯扰动(09-20: 摘 rb 后 wt2 78.52 → 78.91)。E1 的岭把 Δb 往 0 压、E2 的 a_e 只修比例不修偏好、择优尺换成路由代价, 三件都在削域先验; 但削不干净——
**所以守门尺(wt2 + 八域)在终判里成对报**(带路由件 / 摘路由件 同二进制同趟, 一次加载 40 MB 侧车切换是分钟级), 退多少写清楚, 挂不挂由用户定; 本文不替用户摘。
语料冻结(铁律), 不为通用尺往拟合份里加 wt2。

## 3 增益反修: 还剩什么肉, 怎么拿

### 3.1 三张表联合解(数学)

引擎这一层: y[i] = round_bf16( ysh[i] + Σ_k rw[i][k] · ye[i][k] ), 专家 e 内部 ye = W2_q · h, h = silu(clamp(W1_q x)) ⊙ clamp(W3_q x)。
现役只解 **s_e[d]**(乘在 W2_q 的行 = 输出通道)。本轮加两张:
- **t_e[j]**(乘在 W3_q 的行 = 隐藏单元 j, 等价于把 h_j 缩 t_j 倍, 对 y 是线性的): ŷ_e = diag(s_e) · W2_q · diag(t_e) · h。
- **s_sh[d]**(乘在 shared 专家输出通道上): ŷ = diag(s_sh)·ysh + Σ_k rw·ŷ_e。
gate 那张(W1_q 行, 进 silu 是非线性)本轮不解(§6), 只做 up: 线性的一半先拿, 非线性的一半等这一半兑现了再谈。

解法(仍是 Gauss-Seidel 逐专家 + 格点直解, 每轮内交替):
1. **s 步**(现役): 每输出通道 d 一维带岭最小二乘, 与今天逐式同, 只是 u[i][k][d] 里的 ye 换成 W2_q·(t⊙h)(t 全 1 时逐位退化成今天)。
2. **t 步**(新): 专家 e 名下 ~128 个 (i,k) 对, 未知数 2304 个(MID = 2304), 联合解一个 2304×2304 的岭正规方程: G = (W2_qᵀ diag(s²) W2_q) ⊙ (Σ_i rw_i² h_i h_iᵀ)(两个 2304×2304 的逐元素积: 前者每专家一次 syrk 27 GFLOP, 后者 1.4 GFLOP),
   右端 Σ_i rw_i·(h_i ⊙ (W2_qᵀ diag(s) r_i)), 岭 λ_t·diag(G) 锚在 t=1, cuSOLVER potrf(4 GFLOP), 384 专家 ≈ 12 TFLOP/层 = GB10 fp32 上秒级(贵的仍是取料前向, 不是解)。
   ★这一步要专家的 W2_q(5120×2304, 量化后解码值)★: 用引擎自己的 VQ 解码核按专家解一次到 f16(24 MB, 用完即弃), 通过契约头给解算器一个入口, **不另写第二份解码**(铁律: 格式基元只有 src/common 与引擎那一份)。
   解完整支 t 投影到 fp4 格点, 按格点值更新残差, 下一个专家看到的是含它量化误差的残差(与 s 步同一纪律)。
   数据够不够: 128 对 × 5120 维 = 65 万个方程对 2304 个未知数, 且岭锚 1、held-out 兜底——不是欠定问题。
3. **s_sh 步**(新): 当成第 385 个"专家", 名下是全部拟合行, 每通道一维最小二乘, 岭同款。
4. 轮数 3(与现役同), λ 网格 {0.01…1000} 只认 val, t 步单独一档 λ_t ∈ {0.1, 1, 10}(网格 6×3 = 18 格, 秒级一格; 贵的是取料前向, 不是解), 层闸 0.5% 不动(09-15 已用出口尺扫过, 别再调)。
   **必含退化格**: t ≡ 1 / s_sh ≡ 1 的格要在网格里, 让 val 有机会说"这一层只要 down 增益"。

### 3.2 产物与引擎

| 件 | 格式 | 体积 | 引擎 |
|---|---|---|---|
| gr_Lnn.bin(现役, down 行增益 s−1) | `<E><D><43>` + fp4x32 | 1.04 MB/层 | 已有 |
| **gu_Lnn.bin**(up 行增益 t−1) | `<E><MID><43>` + fp4x32 | 0.47 MB/层(384×2304×4.25 bit) | 新: `ds4_gpu_v41_set_gu_override(层, [E][MID])`, 预填融合核 which=1 那一发与解码融合核的 up 行各多乘一个 `m.gov`(与 down 今天的写法逐字同位); NVFP4 存档路同步或硬拒 |
| **gs_Lnn.bin**(shared 输出增益 s_sh−1) | `<1><D><43>` + fp4x32 | 2.7 KB/层 | 新: shared 输出 so 乘表后再加(预填 `add` 前一发小核 / 解码尾核多一个乘) |
| rb_Lnn.bin / ra_Lnn.bin(路由) | 现役格式 / `<E><2>` f32 | 1.5 KB / 3 KB | rb 已有; ra 只在 P3 选中 E2 时建 |
| 落盘自证 | 三张表落盘前用 src/common 唯一解码器回读逐位相等(现役纪律) | | 指纹(ds4_gr_fnv)连 gu/gs/ra 一起算, ③ 后训练件靠它认底座 |
| 部署对体积 | 113.557 GB + ≈ 0.06 GB(gr 40 + gu 19 + gs 0.1 MB) | **113.62 GB**(全字节口径) | 解码字节 +0(表在 L2, 每 token 每层 6×2304×4 B = 55 KB) |

出错会怎样: 覆盖表形状不对引擎硬停(现役 gr 的做法); 表挂上而核没乘 = 读数与不挂逐字节同, **所以 P2 的第一道门是"挂 3 层 gu 的引擎输出 ≠ 不挂"再是"= 解算器预测"**。

### 3.3 行加权(可选臂, 单变量)

09-20 偏置项判负时定位的机理: 层内 L2 按能量吃"典型 token", 出口 KLD 由"难 token"主导, 两者不同向。乘性增益没这个病(比例修正对典型/非典型同比伸缩), 但也可以直接对准出口: 拟合行按现役对在拟合份上的逐位 KL 加权
(w_i = 1 + KL_i/mean, 来自 `v41_judge.sh vqhalf_a 8192 engine:<v3>:<gr>` + `anchor_metrics --row-out`, 零新工具), 解算器的 num/den 求和乘 w_i。只在 P2 主臂过门后作 A/B 臂, 不与主臂混跑。

## 4 方案: 合并序贯链(每层做什么)

第 k 遍(挂 L0..L(k−1) 已落盘的 rb/ra + gr/gu/gs, 到 L(k) 取料即停; 骨架 = 现役 `v41_amp_run --rb <夹具> --capture-ye` 的 rbgr_hook):
1. 钩子同一遍收: 路由统计(s_q 重算 / s_fp 由夹具重算 / A_i / B_i)+ 增益取料(x / y / sel / rw / 逐专家 ye / **h32**(新增捕获, 与 ye 同一种拷贝)/ ysh)。
2. 解路由: P3 选出的估计量(E0 现役 / E1 / E2)按其 val 尺择优, **严格涨才落盘**(现役规则); 落了盘 ⇒ 挂上重取本层(路由变了, 旧料里的 ye/h 是旧专家的)。
3. 解三张增益表(§3.1), λ×λ_t 只认 val, 格点直解, 落盘自证。
4. 末遍全挂跑完整前向打拟合料 PPL(与现役同口径, 参照 11.6208)。
先例: q4k-12 grrb 合并序贯 64 min(前向 2850 + FP 靶 962 + 解 31 s); 本轮多一张 t 表的解(秒级)与 h 捕获(8192×6×2304×4 B = 0.45 GB/层主机内存), 账 ≈ 同档; 内存账 `--weight-cache-mb 88000` 封顶 + 看门狗 8 GB 不变。
**破 2 h 停车查, 不干等**(铁律: 超时 = bug)。

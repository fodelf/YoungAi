01部署

单一手写 Makefile，无 CMake/configure。产物直接落在仓库根目录。

$ make                        # macOS: ds4 / ds4-server / ds4-bench / ds4-eval / ds4-agent (Metal)
$ make cuda-spark             # Linux: DGX Spark / GB10
$ make cuda-generic           # Linux: 本机 GPU (CUDA_ARCH=native)
$ make cuda CUDA_ARCH=sm_120  # Linux: 指定 nvcc arch
$ make cpu                    # CPU 参考/调试构建 (-DDS4_NO_GPU)

Linux 上裸 make 只打印目标列表，必须显式选 cuda-* / cpu。CPU 路径仅作参考与诊断，不是生产路径。

取模型

$ ./download_model.sh q2-imatrix   # 下载至 ./gguf/，并把 ./ds4flash.gguf 软链过去

./ds4flash.gguf 是所有二进制的默认模型；用 -m gguf/<file> 覆盖。仅支持本项目发布的 DeepSeek V4 非对称量化 GGUF（routed expert IQ2_XXS/Q2_K，其余高精度）。

02运行

二进制用途
ds4CLI。-p "..." 一次性问答；不带 -p 进交互 REPL。--metal / --cuda / --cpu 强制后端；从别处启动加 --chdir /path/to/ds4 以解析 metal/*.metal。
ds4-serverOpenAI / Anthropic / Responses 三协议 HTTP 服务，单图 worker 串行推理。
ds4-agent进程内原生 coding agent，会话即磁盘 KV（~/.ds4/kvcache）。会话命令：/list /switch <sha> /save /del /strip。
ds4-bench上下文前沿处的瞬时 prefill/decode t/s（非全程均值）。
ds4-eval内置 92 题能力面测评。
$ ./ds4 -p "Explain Redis streams"
$ ./ds4-server --port 8013 --ctx 100000 --kv-disk-dir /tmp/ds4-kv --kv-disk-space-mb 8192

03Server API

端点：/v1/chat/completions（OpenAI）· /v1/messages（Anthropic）· /v1/responses（Responses）。流式均支持。

$ curl -s http://127.0.0.1:8013/v1/messages -H 'content-type: application/json' -d '{
    "model":"deepseek-chat","max_tokens":256,"temperature":0,
    "messages":[{"role":"user","content":"Write a Go function that reverses a slice."}]}'
  • 磁盘 KV 缓存是续聊机制。渲染前缀 sha1 → <sha>.kv，跨会话/重启复用 prefill；内存里只保留一个活体 checkpoint。
  • 工具调用字节稳定。server 维护 exact-DSML 重放表（tool id → 采样原字节），无状态客户端重发 JSON 也能与活体 KV 逐字节对齐；工具语法段强制 temperature=0。
  • 请求级 frequency_penalty / presence_penalty 按 OpenAI 语义解析，只作用于生成区。

04接入 Claude Code

把 server 当 Anthropic 端点用，零改客户端：

$ ANTHROPIC_BASE_URL=http://127.0.0.1:8013 \
  ANTHROPIC_API_KEY=svc ANTHROPIC_MODEL=deepseek-chat \
  NO_PROXY='*' API_TIMEOUT_MS=3600000 \
  claude -p "修掉 pkg/util 里的竞态" --model deepseek-chat

双机栈下等价快捷方式：tools/svc.sh claude '任务'。长会话受益于磁盘 KV：系统提示词早位变异会自动回卷到分叉点（live-lcp），不整段重灌。

05双机分布式

模型按 transformer 层切片跨机运行：coordinator 持 tokenizer/采样 + 前段层，worker 持后段层，自定 TCP 二进制协议流水。prefill 流水线加速；decode 每 token 一跳跨机。

# worker（先起，监听）
$ ./ds4 -m model.gguf --role worker --listen 192.168.1.2 5599 --layers 20:output -c 65536 --temp 0
# coordinator
$ ./ds4-server -m model.gguf --role coordinator --coordinator 192.168.1.2 5599 \
    --layers 0:19 -c 65536 --port 8013

worker 出站受限时给两侧加 DS4_DIST_REVERSE_CONNECT=1（coordinator 反向连入）。

tools/svc.sh —— 常驻栈服务管理

$ CS_CAP=6 PIPE_CHUNK=2 MODEL=gguf/<model>.gguf tools/svc.sh up   # 拉起两侧 + 12G 看门狗
$ tools/svc.sh status              # 两侧 pid / RSS
$ tools/svc.sh probe '提示词' 64    # 单针探测
$ tools/svc.sh claude '任务'        # 直连 Claude Code
$ tools/svc.sh down                # 只杀进程，不动文件
  • 幂等：已常驻则跳过；server 与看门狗均以独立进程组运行，宿主 shell 清理不连带。
  • 看门狗 tools/svc_watchdog.sh：任一侧 RSS 超 12 GiB，双侧同杀。
  • CS_CAP=6 PIPE_CHUNK=2 为实测冠军配置（copy-speculation 批长封顶 + verify 批跨机分块流水；fresh +34%，edit +63%）。

06调优旋钮

全部 env 均围绕单一 release 路径的诊断/调优开关，默认值即当前稳定基线；不设不改即最优起点。

变量作用
DS4_MEM_BUDGET_MB内存预算闸。启动时驻留规划超预算即拒绝，运行时配合看门狗。
DS4_DIST_CS_LEN_CAPcopy-speculation 单批草稿长度上限。稀疏 MoE 下 verify 行不去重专家，长批净亏；甜点 4–8。
DS4_DIST_PIPE_CHUNKverify 批按行分块跨机流水，隐藏一跳延迟。
DS4_METAL_PREFILL_CHUNKprefill 分块大小（默认 2048）。
DS4_METAL_EXPERT_PREADrouted expert 走单拷贝直读（绕 mmap 缺页 + memcpy）。
DS4_LOOP_ESC / DS4_LOOP_HARD_K / DS4_LOOP_BREAK生成区重复退化分级惩罚：第 k 轮重复罚 ESC·(k−1)，到 HARD_K 轮硬禁；BREAK=0 总关。合法有限重复可穿透，退化环被掐。
DS4_MTP_SPEC_DISABLE关闭 MTP/投机路径（诊断用）。

09硬约束

macOS 禁大跑 CPU 路径。CPU 推理在 macOS 上可触发内核崩溃（OS VM bug）；CPU 仅限小规模参考/诊断。
单实例锁是有意为之。不并发跑多个巨模型进程；同一台 16G 机器绝不双载 80G 级底模。
双机 12 GiB 红线。两侧 RSS 上限 12 GiB，看门狗越线双杀；任何加载模型的脚本必须先过内存账。
加载保持 mmap-backed，永不整模型急拷贝；别再给 mmap 模型加显式 RAM 专家缓存/mlock 钉扎 —— OS page cache 已用 LRU 把内存吃满，抢它净变慢（两次实测判决）。

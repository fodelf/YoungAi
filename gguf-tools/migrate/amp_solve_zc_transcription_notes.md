## A 影响数值(全部照抄, 无一处"顺手改好")

1★ **SVD 是唯一的算法替换。** numpy `np.linalg.svd`(LAPACK gesdd) → C 侧走
   **随机子空间迭代 + Rayleigh-Ritz**(过采样 p=256, 幂迭代 q=2, 每半步正交化)。
   数学上求的是同一个主子空间, 但**符号约定**、**简并子空间内的旋转**、以及**截断边缘
   附近方向的混合**由算法决定, 与 numpy 不同。实测(夹具, PCA 当选): V 块 768 列里
   371 同号 397 反号、**无一列"都不是"**; A 块 765/768 只差符号, 另 3 列不是 —— 那 3 列
   正落在 pca2 门的截断边缘(Vt 第 1024..2048 行), 是子空间法精度最低的位置。符号对结果
   无影响(tanh 奇函数, 基列翻号被 U 对应行翻号抵消), 但**载荷字节必然不同**。
   ⚠ 这条只在 V₀=PCA 或 门=pca2 当选时才落盘 —— 而 .py 的 215 条历史解算记录里
   **PCA 从未当选**(V₀=rand 100% 胜、门=rnd2 98.6% 胜), 所以实战中这条不进产物。

1b★ **首版(行 Gram + 全特征分解)为什么被推翻 —— spark 真数据崩溃归因(2026-08-25)。**
   现象: L20 真 zcache(S=8192 D=4096 DIN=12288 NFIT=6553 → na=13106) 报
   `tqli: 第 0 个特征值 60 轮不收敛`, 同输入 .py 正常出数(258s, held 2.47% @rand/rnd2)。
   两个独立的硬伤, 都不是"调参数"能治的:
   - **取错了 Gram 那一边**: na=13106 > DIN=12288, 首版无条件走行 Gram(na×na), 取到了
     大的一侧, 而且 Gram 秩亏 818。(我的夹具是 na=2048 ≤ DIN=2100, 恰好绕开了这个形状。)
   - **QL 的收缩判据是纯相对判据**: `|e[m]| + dd == dd`。特征值动态范围一旦超过 1/ε
     (≈1e16 —— 秩亏 + 激活谱重尾时必然), 小特征值那端的 e[m] 里全是大特征值留下的
     ~ε·‖T‖ 舍入噪声, 相对判据**永远不可能满足** ⇒ 迭代上限耗尽。**调高上限治不了。**
   已排除的假设(都在 Mac 上单独复现过, 都不致命): 秩亏本身(1400×1200 秩亏通过)、
   dither 成对近重复结构(1800×1500 带 dither 通过)、输入 NaN(无)。是**规模 + 动态范围
   一起**才炸。
   附带发现: 即使收敛, 全特征分解也是废设计 —— 实测 n=2000→3.6s、n=4000→28s(≈n^3.2),
   外推 n=13106 ≈ **16 分钟**, 而 QL 的特征向量累加天然串行, 并行不掉。**拿全特征分解去
   取前 16% 的方向本身就是错的工具。**

1c 保留下来的 tridiag/build_QT/tqli **只在 L=nv+256(≈2304)阶用一次**(Rayleigh-Ritz 的
   小稠密特征分解, 约 4s), 稳在舒适区。同时补了两处硬化: ①收缩判据加**绝对下限**
   `|e[m]| ≤ ε·dd + ε·‖T‖`(LAPACK dsteqr 同款, 正是 1b 第二条的对症修法);
   ②入口检查 d/e 非有限就直接报错 —— 否则 NaN 会伪装成"不收敛"这种误导性症状。

1d **每半步都要正交化, 不是每整步。** 整步才正交时一步的条件数是 (σ₁/σ_L)², 衰减谱下
   轻易破 1e8, 子空间数值塌掉。实测 13106×12288 / 1/(1+i) 谱, 每整步正交时数值秩从 2112
   塌到 1148, 尾部近千个方向被迫重随机化 —— **那些方向就是算错的**(改成每半步正交后
   尾部 σ 从 0.0176 变成 0.0487)。这个坑不报错, 只是悄悄给出错的基。

1e **秩揭示 + 重随机化不是兜底。** Cholesky 主元 ≤ n·ε·max(diag) 时说明 Y 的数值秩 < L,
   那些方向对应 σ=0 —— numpy 的 gesdd 同样只是返回零空间里的**任意**正交补。所以正确
   做法是换一批新随机向量再正交化(同一条确定性流, 工具仍然同输入→同输出), 不是报错。
   4 轮仍不行才停车。夹具 A 就走了这条: 数值秩 2047 = 2048−1(减均值吃掉一维), 尾部 1 行
   重随机化, 结果与 .py 完全一致。

1f **CholQR2 的 Cholesky 必须用【已缩放的第 k 列】做尾更新。** 我第一版拿了第 k 行 ——
   上三角还留着未缩放的原始对称值, 拿它更新会把因子算坏, 而且表现成"起始块主元 ≤ 0"
   这种看起来像数值退化的假象(随机高斯起始块根本不可能退化, 这就是识别信号)。

2★ **精度阶梯**(最容易被"顺手改好"的地方, 与 zlayer 清单 #2 同款坑):
   `dH`/`yq`/`yfp`/`eps` 全是 f32; `R = (dH*yq/(yq²+eps²)).astype(f64)` **括号里整段 f32**,
   只在最后升一次 f64。`colw = sqrt(var₀(R[tr])+1e-12) * sqrt(mean₀(yq[tr]²)+1e-12)` 左半 f64
   (R 已升)、右半 f32(m2 还是 f32)、乘积 f64。`1e-2`/`1e-12`/`1e-6` 这些 Python 标量按
   NEP50 弱标量降到 f32 参与运算, 不提升数组精度。

2b **NaN 入口守卫**(lead 点名的第 ③ 条)。dH / yq / X0(xcap 或锚 fin)装载后立刻逐元素查,
   SVD 入口再查一遍 Xa−mean, tqli 入口查 d/e。坏值往下走会**伪装成别的症状** ——
   "held=nan → 层闸"(静默丢一层)或特征分解"不收敛"(误导性报错), 所以必须在入口拦并
   报清楚是哪个量的第几个元素。实测: 往 dH[123,45] 注 NaN → `Error: zcache dH 第 86145 个
   元素非有限(nan)`。守卫本身不改任何数值(加守卫前后夹具输出逐字节不变)。

3★ **`yfp - yq` ≠ `dH`。** `yfp = yq + dH` 是 f32 加法, 所以 `e0` 里的 `(yfp[ev]-yq[ev])`
   带着一次 f32 往返舍入, 不等于直接用 dH。少走这一步 e0 会差, 整条 held% 跟着漂。
   同理 `rec` 里 `yh = yq*(1+g)` 的 g 必须先 `.astype(float32)` 再进乘法(矩阵乘本身是 f64)。

4  **numpy 的两套归约都要复刻。** 归约轴连续(整块 `.sum()`、`.mean(axis=1)`)走 pairwise
   求和(块 128、8 个累加器、`n2 -= n2%8` 的切法); 归约轴不连续(`.mean(axis=0)`、`.var(axis=0)`)
   走朴素逐行累加。累加类型也照抄: f32 数组的 mean 用 **f32** 累加器。`np.trace` 是跨步视图
   ⇒ 朴素求和。文件里 `pw_sq_f64/pw_sq_f32/pw_sqdiff/pw_sqres` 是前者, 手写循环是后者。

5  `np.add.at(yq, prow, pw[:,None]*pYQ)`: 乘积**先在 f32 舍入**再无缓冲累加, 累加顺序 = 对序
   (不是按 token 分组)。与 zlayer 清单 #7 同款。

6  `_phi` 里 `(M*M)` 算了两遍(一遍算 rms、一遍做中间块), 值相同; `np.maximum(M,0)` 用
   `v>0?v:0`(−0.0 → +0.0, 两者数值都是零, 且只作为乘法操作数, 无影响)。

7  `np.linalg.solve` = LAPACK **dgesv(部分主元 LU)**, 不是 Cholesky。G 虽是对称正定,
   换 Cholesky 更稳但求和顺序不同 = 改数。★换代 amp_solve.c 用的是 Cholesky, 别抄过来。★
   C 侧右端项按**转置布局**(nrhs 行 × n 列)解, 前代/回代全连续访问 —— 只是内存布局,
   不改任何一次浮点运算的操作数。

8  GEMM/LU 的求和顺序与 BLAS 不同(BLAS 分块+向量化), f64 尾位差 ~1e-13 相对。**有/无
   `-DDQ_BLAS` 两种构建之间也不逐位**(zlayer 清单 #9 同款既判)。U 落 f16(11 位尾数)后
   绝大多数条目相同, 但边界值会翻末位 ⇒ 整文件 md5 不作判据。
   带 `-DDQ_BLAS` 时 CholQR 的前代额外走 `cblas_dtrsm`(手写路是二级循环, 实测真尺寸
   SVD 62.5s → 24.4s), 同样落在这条"两种构建不逐位"里。

9  **FMA 合并必须关掉。** `#pragma STDC FP_CONTRACT OFF` 放在 include 之后(clang 认;
   实测默认构建与 `-ffp-contract=off` 构建输出逐字节相同, 说明 pragma 生效)。gcc 只认命令行
   开关, 但任务指定的构建行不带 `-march`, 基线 x86-64 无 FMA, 默认安全。**加 `-march=native`
   时务必同时加 `-ffp-contract=off`。**

10★ **macOS 上别拿本机 numpy 当 RNG 金标。** arm64 的 numpy 2.5.1 把 legacy_gauss 里
   `r2 = x1*x1 + x2*x2` 编成了一条 FMA, r2 差 1 ULP。实测 200 万次抽样 **13.79%** 的高斯值
   与非 FMA 写法差 1 ULP —— Mac 上 `RandomState(1).randn(8)` 会有一个(第 3 个)对不上,
   **这不是转录错**: spark(Linux x86-64)上 numpy 不合并, zlayer.c 同款 RNG 段已在那边过了
   逐位金标。而且这 1 ULP 到不了产物: 同样 200 万样本 `×1/√DIN` 落 f16 后 **0 个不同**;
   生产尺寸 12288×1024 的 seed 7/11 两条基与 numpy **12582912/12582912 逐位全同**。
   要复核 RNG 请在 spark 上做, 或直接比 f16 基。

11 四个投影 `tanh(X·V/s)` / `tanh(X·A/s)` 提到 (nm,gn) 双循环外面。.py 在每个组合里重算一遍,
   值完全一样 —— 纯省 4× 矩阵乘, **不是数值改动**(每个元素的操作数与舍入逐位相同)。

12 `best` 里存的是 `U/colw`(已除)而不是 .py 的裸 U。.py 在网格里除一次、出载荷时再除一次,
   两次是同一个 f64 除法, 逐位等价; C 侧只除一次并复用。

13 平局保先: 判据是 `rec > best` **严格大于**, 所以迭代顺序决定平局归属 ——
   `PCA→rand` × `pca2→rnd2` × λ `1000,300,100,30,10,3,1` × k `16,32,64,128,256,384,512,768,1024`,
   一个都不能换。

14 层闸分支写的记录名是 **`zl.AMP`**(不是 `zl.AMPD`), 载荷长 0。.py 两个分支名字就不同,
   照抄不统一 —— 合并器按 psz<16 判层闸, 名字只是标记。

## ★关于 lead 给的自测判据 ‖Y−UΣVᵀ‖/‖Y‖ < 1e-10

这个判据只在 **rank(Y) ≤ nv** 时可达, 对满秩输入**任何正确实现都不可能满足**, 包括
numpy 自己 —— 因为我们只取前 nv=2048 个方向, 残差恒等于被截掉的尾部能量
√(Σ_{i>2048}σ²/Σσ²)。对 13106×12288 的两档谱, 这个值分别是 ~1.5e-2(1/(1+i))和
~0.77(平谱), 是数学下界不是精度。所以自测里做了拆分:
- rank ≤ nv 的构造 → 直接验 1e-10(实测 4.33e-15 ✓);
- 满秩构造 → 改看**正交性**、**Ritz 残差 ‖Yᵀ(Yv)−σ²v‖/λ₀**、**与 numpy 的 σ 对表**,
  并把尾部能量的理论期望值一起打出来, 免得下次有人再拿这个数当 bug。

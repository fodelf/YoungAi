# 冷热双通道反修 + op 烘焙通路 — 落地设计(2026-08-06 用户裁决)

## 裁决背景
1. **指标≠可用**(r55 实证): 反修过程账 +38.5%、五指标"改善", 但 Python 7/17。
   根源之一 = **op 通路断链**: 8-04 平行架构(dql 只读+op 侧车唯一落点)漏配套合并消费,
   vq_merge_v4.py 只读 dql/dql_vq 裸字节 ⇒ 合并模型=裸量化+RB 烘焙, 反修增益从未进产线;
   五指标(学生回放=dql+op 全应用)与 40 题(裸合并模型)测的是两个不同的模型。

   完全不同, 而 GL(层标量)/GLdyn2/GLdyn8(层动态)/zl.RRR(方向修正)全是一层一套冷热合用
   ⇒ 对热过修、对冷欠修互相拖累。唯 GE(256 每专家)天然分离。

## P1 — 冷热双通道系数(基础方案不变, 系数模式拆分)
**分桶定义**: 专家 id ∈ 当层热表(GO2B_HOT_TABLE, top49/topN) ⇒ hot, 否则 cold。
一个 token 的 top-6 常混冷热 ⇒ 按**贡献项**分桶, 非按 token 分:
`routed(x) = R_h(x) + R_c(x)`(选中热/冷专家的加权贡献和, 捕获期分离累计)。

| 组件 | 现状(冷热合用) | 双通道设计 |
|---|---|---|
| bf.GL 层标量 | y≈g·R | y≈g_h·R_h + g_c·R_c(2×2 正规方程闭式, 求解器现成模式) |
| bf.GLdyn2 | c(x)=w0+w1·zn(‖Fin‖) 乘整层 | hot/cold 各一组 (w0,w1): c_h(x)·R_h + c_c(x)·R_c(4 参数 LS) |
| bf.GLdyn8 | PCA8 9-dof 乘整层 | hot/cold 各 9-dof(18 参数; 同一 PCA 基, 双通道行乘) |
| zl.RRR | 层出口方向修正 U·V | 双通道: RRR_h 作用于 R_h、RRR_c 作用于 R_c(载荷×2, 秩梯子同闸) |
| bf.GE | 256 每专家增益 | 不变(天然分离) |
| 四损失/感知行权 | 行级加权 | 不变(作用于求解目标, 对两通道同权) |
| 路由 FIT/烘焙 | Δb per-expert | 不变(天然分离) |

**op 侧车新类型**(DQL2 记录同格式): `bf.GLhc`(8B: g_h,g_c) / `bf.GLdyn2hc`(16B) /
`bf.GLdyn8hc`(72B) / `zl.RRRhc`(2×RRR 载荷)。回放端(bytes_moe op 循环)按热表分桶应用。
判据/流程(ONEPASS 粗筛→终验→劣化回滚→GSWEEP)零改动 — 只有候选形态的求解与应用变。

## v2 追加(2026-08-06 用户裁决)
### 流程重排 — 反修阶段一切生效(环境一致性铁律)
病根: op 在"无 RB"环境求解, 运行时与 RB 首次同场 ⇒ 优化环境≠部署环境, t0 负迁移主嫌。
新流程: 量化(FIT 统计, α 权威=2.5)→ rb_save → **反修前向挂 DS4_ROUTE_BIAS(RB 在场解 op)**
→ 合并=纯打包(op 内嵌 + 同值 Δb 烘焙), 合并不再引入任何优化期未见过的变量。
不变量: 反修终验环境 ≡ 部署环境(路由偏置/op 全同场)。

### 冷热来源与组件族全拆分
冷热名单=配置权威(plan_config.json + per-layer 热表, 量化器已消费), 非运行时推断。
组件族整套按桶: z(GL/dyn2/dyn8 hot+cold 双套) / 四损失(λ 结构按桶) / 感知(行权 kk 按桶
残差能量) / 路由 GE+Δb+烘焙(per-expert 天然分离, 不改)。
